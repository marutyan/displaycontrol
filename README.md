# DisplayControl

MacBookの内蔵画面と、DDC/CIに対応した外部モニターの輝度を、輝度キーとメニューバーから操作するmacOSアプリです。メニューバーに常駐します。

開発に使った環境はMacBook Pro（M3 Pro）とDell S2725QC 2台です。それ以外の機種での動作は確認していません。

## 操作

| 操作 | 動き |
| --- | --- |
| 輝度キー | 接続中のすべての画面を1段（1/16）ずつ変える。上限か下限に届いた画面だけそこで止まり、画面どうしの明るさの差はそれまで保たれる |
| Shift＋輝度キー | Active画面だけを1段変える。長押しすると変え続ける |
| 輝度キーの上下を同時に押す | すべての画面を、Active画面の明るさにそろえる |
| メニューの各画面のゲージ | その画面だけを変える |
| メニューの「Match All to Active」 | すべての画面を、Active画面の明るさにそろえる |

Active画面は前面のアプリのウインドウがある画面です。自動で決まります。

- デスクトップをクリックした後は、クリックした画面がActive画面になります。
- 前面のアプリにウインドウが無い場合は、マウスポインタのある画面がActive画面になります。
- それでも決まらない場合は、macOSの主画面がActive画面になります。

キーで操作すると、マウスポインタのある画面の下寄りに、操作の対象と明るさを示す表示（16段のバー）が短い時間出ます。

## ビルドと起動

必要なものはmacOS 26以降とSwift 6.2以降です。

```sh
scripts/build-app.sh        # dist/DisplayControl.app を作る（インストールはしない）
open dist/DisplayControl.app
swift test                  # 単体テスト
```

輝度キーを使うには、アクセシビリティの許可が必要です。メニューの「Enable Brightness Keys…」から、システム設定のアクセシビリティでDisplayControlを許可してください。

`build-app.sh`はキーチェーンにApple Developmentの証明書があれば、それで署名します。証明書で署名すると、アプリを作り直しても許可が保たれます。証明書が無い場合はアドホック署名になり、作り直すたびに許可が外れます。外れたら、システム設定でDisplayControlの古い項目を削除してから、許可し直してください。

`DisplayControl --diagnose`を実行すると、画面の検出結果と現在の輝度を表示して終了します。輝度は読み取るだけで、書き込みはしません。

## 仕組み

- 内蔵画面の輝度は非公開のDisplayServicesで読み書きします。
- 外部画面には非公開のIOAVServiceを通してDDC/CIの命令を送ります。
- 非公開のAPIは起動時に動的に読み込みます。見つからない場合、その種類の画面は操作の対象から外します。macOSの更新で使えなくなる可能性があります。
- 外部画面はEDIDのメーカー、製品番号、シリアル番号で識別します。同じ型の2台も区別できます。
- 書き込むたびにEDIDを読み直し、画面が差し替わっていれば書き込みません。
- 起動時、画面構成が変わったとき、スリープから復帰したときは、輝度を読むだけです。書き込むのはユーザーが操作したときだけです。
- 書き込みは画面ごとに別々の経路で行います。ある画面の通信待ちがほかの画面を止めません。
- 同じ外部画面への命令は50ms以上の間隔を空けて送ります。続けて操作した場合は、待ちが終わった時点の最新値だけを送ります。
- 上下を同時に押したかを見分けるため、Shiftなしの輝度キーは最大75ms待ってから反映します。75ms以内に反対のキーが来れば同時押しとみなし、来なければ1段変えます。75msより早くキーを離した場合は、離した時点で反映します。

## 確認済みの範囲

- 内蔵画面とDell S2725QC 2台で、1段下げて読み戻し、元の値へ戻せること。
- 物理キーでの操作（単押し、長押し、Shift＋輝度キー、上下の同時押し）。
- 外部画面を抜き差しした後も操作を続けられること。
- 画面収録の許可なしに、前面のウインドウからActive画面を判定できること。
